我这个学期之前的学习路径很标准：Burp 抓包、sqlmap 跑注入、pikachu 靶场一道道刷、
顺手做点源码审计。这套东西让我对"怎么打进去"有了一点手感。

但前阵子开始写一个日志分析工具，突然卡住了。

因为红队的问题永远是"我怎么才能进去"，而蓝队的问题我从来没回答过：

> **他进来的时候，我会不会知道？**

## 一、两种思维，几乎相反

| | 红队 | 蓝队 |
| --- | --- | --- |
| 目标 | 拿到权限 | 看见并阻断 |
| 成功标准 | 进去了 | 报出来了，而且是真的 |
| 怕什么 | 被发现 | 没发现（漏报） |
| 优化方向 | 更强的利用链 | 更低的误报率 |

红队只要**找到一条**可行路径就算成功；蓝队必须**堵住所有**路径才算安全。
这是一个根本性的不对称——防守方永远处于被动。

理解了这一点，我才明白为什么安全行业里说"防守是成本问题，不是技术问题"。

## 二、蓝队的工作是一个闭环，不是一个点

我一开始以为"日志分析"就等于"蓝队"。后来才理清完整链条：

1. **日志产生** —— nginx 访问日志、sshd 认证日志、数据库审计
2. **采集与存储** —— 集中收集、防篡改、按等保要求留存 6 个月以上
3. **解析与归一化** —— 非结构化文本变成结构化字段
4. **检测** —— 特征规则 + 行为基线
5. **告警与研判** —— 分级、去重、关联，人工或模型确认
6. **响应与复盘** —— 封禁、取证、加固，把经验写回第 4 步的规则里

第 6 步回到第 4 步，这个环才闭上。

**我写的工具只覆盖 3、4、5 三个环节。** 这句话很重要——面试官问"你这个项目在真实体系里处于什么位置"，
如果你答不出边界，就说明你没真正理解自己做的是什么。

## 三、检测只有两条路，而且必须一起走

### 特征检测

拿已知的攻击特征去匹配。本质就是正则。

- 优点：准、快、可解释，几乎零误报
- 缺点：**只能抓已知的**。改个大小写、套一层 URL 编码就绕过了

### 行为检测

看行为的统计特征是否符合"机器"模式。

- 优点：不依赖具体 payload，改语法也绕不过去
- 缺点：容易误报，需要先建立基线

举个例子：不管扫描器用什么 payload，
它一定会在几十秒内产生大量 404，而且**路径是分散的**。
这个行为特征是绕不掉的。

反过来，一次成功的 SQL 注入可能只有一条请求，行为上完全不异常——
这时候只能靠特征检测。

所以真实产品（WAF、SIEM）都是两路并行取并集。我第一版只做了特征检测，
而且做得还很粗糙，后面那篇文章会讲后果。

## 四、第一性原理：四个格子

这是我目前认为整个蓝队最核心的一张表：

|  | 实际是攻击 | 实际是正常业务 |
| --- | --- | --- |
| **系统告警** | 真正例 TP | 假正例 FP（误报） |
| **系统放过** | 假负例 FN（漏报） | 真负例 TN |

两个指标：

```
精确率 Precision = TP / (TP + FP)   我报出来的，有多少是真的
召回率 Recall    = TP / (TP + FN)   真的攻击，我抓到了多少
```

**这两个指标天然对立。** 阈值放松，召回率上去、精确率下来；阈值收紧，反过来。
没有免费的午餐，全部功力就在于选一个合适的平衡点。

### 为什么误报比漏报更"现实"

理论上漏报更危险——真入侵被放过了。但工程上，**误报会间接导致漏报**：

系统每天报 5000 条，其中 4900 条是误报 → 分析师开始不看告警，直接批量关掉
→ 真正的那 100 条被一起关掉 → 等于漏报。

这个现象叫**告警疲劳（Alert Fatigue）**。所以"降误报"不是优化项，是生死线。

这也解释了为什么很多公司宁愿检测能力弱一点，也要保证告警是可信的。

## 五、告警分级和响应，我记下来的几条

常见四级制：P1 严重（已确认入侵）/ P2 高（高度可疑）/ P3 中（攻击未成功）/
P4 低（扫描探测）。

两个 KPI：
- **MTTD**：平均检测时间，入侵发生到被发现的间隔
- **MTTR**：平均响应时间，发现到处置完成的间隔

被问到"防守方最该优化什么"，答"缩短 MTTD"比答"买更贵的设备"专业得多。

应急响应六阶段 **PDCERF**：准备 → 检测 → 遏制 → 根除 → 恢复 → 总结。

其中最容易做错的是顺序：**遏制一定在根除之前**。
新人看到木马第一反应是删掉，但攻击者可能还在线，删了立刻又被种回去。
正确做法是先隔离网络（而且不要直接关机，内存里有证据），再谈清除。

## 六、我现在怎么理解这件事

写这个项目之前，我以为"安全"就是"把洞补上"。
现在觉得，蓝队本质上是在做一件很朴素的事：

> **把"发生过什么"变成"可以复现的判断"。**

日志是事实，检测规则是把事实翻译成判断的语法，报告是判断的载体。
整套东西的价值不在于抓住多少黑客，而在于让组织在真的出事时，
能在几分钟内回答"他什么时候来的、做了什么、动了哪些数据"。

这个认知转变，比我会用多少个工具重要得多。
